# 从传统数据工程到 AI 数据工程

传统数据工程师不是 AI 时代最容易被淘汰的人群之一，反而是最接近 AI 数据工程的人群之一。关键是把已有能力连接到模型训练目标，而不是停留在表、任务和报表交付。

## 责任对象发生了变化

传统数据工程常以表为交付对象：

```text
业务事件 → 清洗建模 → 指标表 → 报表或应用
```

AI 数据工程以可训练数据版本为交付对象：

```text
原始内容 → 质量与治理 → Token Sequence → 训练 → 评测 → 数据改进
```

第二条链路多了三个关键责任：样本语义、训练系统、模型反馈。

## 已有优势

数据工程师已经具备很多难以替代的基础：

- 能把复杂业务过程拆成稳定数据层；
- 理解分区、Shuffle、倾斜、批处理和容错；
- 重视血缘、口径、质量和可复现；
- 能建设长期运行而不是一次性 Notebook；
- 知道生产结论必须来自日志、产物和回读。

这些能力直接适用于大规模语料加工和训练数据平台。

## 必须补齐的部分

### 模型如何消费数据

需要理解 Token、Sequence、Mask、Batch 和 Loss，才能判断一次文本处理是否改变训练语义。

### 语义质量

空值、唯一键和 Schema 只能保证结构质量。训练数据还需要处理近似重复、知识密度、语言、领域、安全、许可和评测污染。

### 训练与 I/O

需要理解 DataLoader、GPU 等待、训练并行和 Checkpoint，才能把数据吞吐与训练成本联系起来。

### 实验闭环

不能只凭规则通过率宣布数据更好。必须固定训练条件，通过 Loss、能力评测和失败样例验证数据版本变化。

## 推荐的 T 型能力

纵向深度选择“训练数据质量与数据资产”：

- 数据构造；
- 质量、去重和治理；
- Dataset Manifest 和血缘；
- 数据版本 A/B 与模型评测。

横向宽度覆盖：

- Tokenization 和训练基础；
- smallpond 等数据计算系统；
- 3FS 等 AI 存储系统；
- DataLoader、分布式训练和 Checkpoint。

不需要一开始同时成为算法研究员、CUDA 工程师和存储内核专家。先完成一条端到端链路，再根据真实瓶颈选择纵深。

## 职业成果应该长什么样

完成本项目后，最有价值的作品不是“读完了多少论文”，而是：

- 一个可复现的训练数据版本；
- 一份可以追到原始文档的 Manifest；
- 一条 smallpond 数据加工 Pipeline；
- 一次 DataLoader 或 Checkpoint 性能诊断；
- 一次固定预算的数据版本 A/B；
- 一篇明确区分本地、集群和生产证据的技术报告。

这些成果同时体现传统工程可靠性和 AI 时代的模型意识。
